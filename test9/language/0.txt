1.1 DanceVrush是一款基于VRChat平台开发的多人虚拟现实音乐舞蹈游戏

1.3 简体中文版协议为权威版本，如其他语言版本存在理解差异，请以中文版为准

我们是由多方组成的开发团队：

7. 您的隐私安全
我们深知隐私保护的重要性，在此向您详细说明：
7.1 我们收集的数据范围：
   - 仅收集基础游戏成绩数据和您所在的国家信息（用于排行榜与统计分析）
   - 绝不收集任何用户身份信息、语音内容、社交互动记录等敏感信息
7.2 数据收集规则：
   - 在您没有主动根据上传流程指示进行操作时，我们不会收集任何信息
   - 只有当您明确根据上传流程指示进行操作时，我们才会收集并上传您的游戏成绩
7.3 数据保护措施：
   - 我们使用专业的加密技术来保护您的成绩数据
   - 确保数据在存储和传输过程中不会被泄露

   - 您可以随时联系我们删除您的游戏成绩数据
   - 出于安全考虑，我们需要您提供一些基本信息来确认身份（如VRChat账号主页截图等）
   - 也可以通过游戏内联系方式提出删除请求
7.5 处理时效承诺：
   - 我们将在收到请求后的30个工作日内完成处理
7.6 数据保留政策：
   - 服务器内的成绩数据会持续保存，直至用户主动请求删除或项目终止
   - 注：如遇停止维护、服务器到期或自然灾害等不可抗力情况可能导致数据丢失

15. VR设备安全指南
为了您的健康和安全：
15.1 使用建议：
   - 初次佩戴VR设备建议先短时间适应
   - 游玩区域建议不小于3米×3米
   - 确保地面平整且无障碍物
15.2 健康警示：
   - 可能引发光敏性癫痫或晕动症
   - 16岁以下玩家需在成人监护下游玩
   - 建议单次游玩不超过15分钟
   - 每日累计游玩不超过3小时
15.3 安全提示：
   - 请在安全、无遮挡的空间游玩
   - 注意头戴设备、电缆及周围环境
   - 如感不适，请立即停止并寻求医疗建议
15.4 特别关怀：
   - 孕妇、心脏病患者、精神疾病患者等建议咨询医师后再游玩
   - 游玩前请摘除可能造成不适的佩戴物
   - 建议保持室内适当通风
   - 请勿在疲劳、醉酒或服用药物后使用VR设备
   - 建议每隔15分钟休息5分钟
   - 游玩时请保持充足的光线

Test 3 介绍


【项目概述】

Dance Vrush 是一款在 VRChat 平台上开发的音乐节奏类世界，其设计理念与核心玩法完全基于街机游戏 Dance Rush Stardom。玩家可以在虚拟环境中通过脚部动作完成节奏踩踏，体验真实的舞步互动玩法。


【玩法说明】

1. 基本玩法
   - 游戏采用虚拟舞板，玩家通过脚部追踪器进行踩踏输入。
   - 所有游戏逻辑与玩法规则均参考 Dance Rush，包括音符类型、节奏结构、踩踏方式等。

2. 判定系统
   - 游戏包含多段节奏判定，用于区分不同的踩踏时机。
   - 判定核心基于玩家脚部触碰舞板的时刻与谱面时间点进行比对。

3. 谱面系统
   - 支持从 Dance Rush 官方源文件转换而来的谱面。
   - 支持玩家自定义歌曲及其对应谱面。
   - 世界仅支持单人模式，不开放双人游玩。


【输入与交互】

1. 输入方式
   - 完全依赖 VRChat 的脚部追踪系统，玩家需拥有至少双脚 Tracker。

2. 判定原理
   - 系统在玩家踩踏舞板区域时触发输入事件，并根据内部判定时间轴计算结果。

3. 自定义设置
   - 提供 Note Speed 调整功能。
   - 提供音效类型（SE Type）切换。
   - 提供判定时机校准（Offset）。
   - 提供相关的辅助视觉与节奏调整选项。


【场景与视觉设计】

1. 场景结构
   - 世界整体采用黑色墙壁与黑色地面，以提升视觉集中度。
   - 舞板区域位于场景中央，确保玩家活动空间安全、独立。

2. 节奏视觉效果
   - 在歌曲播放期间，场景两侧墙壁会根据音乐节奏产生蓝色动态光效。
   - 若歌曲包含 MV，前方大型视频屏幕将自动播放对应影像。

3. 观众区域
   - 观测区布局在不会影响玩家步伐的位置，确保体验与安全性。


【音乐与版权说明】

1. 世界使用的部分音乐与谱面来自 Dance Rush 官方源文件。
2. 世界同时支持玩家自制曲目。
3. 本项目尚未获得任何官方版权授权，所有内容仅用于非商业、学习与实验性质。


【总结】

Dance Vrush 致力于在 VRChat 中还原基于脚部节奏输入的音乐游戏体验，通过简洁的场景设计、节奏光效、脚部追踪判定与可扩展的谱面支持，为玩家提供接近街机原作的沉浸式节奏玩法。

关于项目的起源

1.
最初我并没有计划制作一款类似 Dance Rush 的游戏。事实上，在创建此项目的早期阶段，我甚至从未真正接触过 Dance Rush。

2.
项目的初始方向原本是 MaiMai DX。但由于当时缺乏开发复杂脚本与模型的能力，加上 MaiMai DX 的原始文件并非以明文形式存储，即使 GitHub 上已有可用于解密的项目，对于当时的我而言，解密流程仍然过于困难，因此搁置了这一方向。

3.
后来，我在 UDON SABER 中体验到 feet saber 模式，感觉脚部输入的方式相当有趣，便开始在 Beat Saber 社群中寻找对应的谱面，并注意到大量谱面其实是基于 Dance Rush 制作的。于是我请求 ちしゃねこ 在 UDON SABER 添加一些 feet saber 谱面，但实际在 UDON SABER 中的体验并不理想。
在多次尝试后，Test 3 正式从 MaiMai DX 方向转向 Dance Rush，并将 MaiMai DX 计划顺延至 Test 5。Test 3 于 2024 年 6 月 15 日首次公开发布。


关于项目框架的迭代

1.
Test 3 的第一个版本是在 24 小时内完成并立即上传至 VRChat。当时我几乎不懂 Unity，也不了解脚本开发的规范，只是凭借几段 YouTube 教学视频便匆忙实现了功能。因此最初版本的整体效果极不理想，几乎无法正常游玩。

2.
框架版本 1 至 3.5 都处于类似状况，只是在原本就相当粗糙的基础上不断修补，并无太多值得描述的结构性改进。

3.
真正意义上可供游玩的版本出现在框架 4.0。大约在 2024 年 8 月，我发布了框架 4.0 更新。虽然该版本仍不算成熟，但至少构建了完整的基础架构，包括谱面解释器、玩家控制器、同步控制器、Setting 菜单等核心功能。
在框架 4.0 的开发过程中，我曾在 MEROOM 336号室 遇到一位玩家并与他进行简短交流。当他得知我在完全不懂 C#、C++、Java 的情况下尝试完成此项目时，他建议我系统地学习一门语言，否则将难以顺利推进开发。
当时我没有采纳这一建议，并表示只在需要某项功能时再去学习对应知识。虽然事实证明这种「现学现用」的方式最终让我完成了 Test 3 与 Test 9，但回头来看，那位玩家的建议非常中肯。如果当时能静下心来系统学习，也许能更早抵达 Test 9 的完成度。但在那个阶段，我对制作 Dance Rush 十分感兴趣，却对编程本身并无太大兴趣，因此选择了当时自认为最轻松的方式继续推进项目。

4.
框架 4.0 存在一个严重结构性问题：为图方便，我直接采用了最简化的数据解析方式，将 Note 尺寸视为固定值。这一错误假设导致实际运行时出现大量问题。因此在框架 4.5 中，我重写了谱面解释器，并加入了自定义谱面支持、本地化支持等功能。

5.
框架 4.5 持续使用了约一年。虽然经过不断修补后勉强可以游玩，但依旧存在大量问题，包括低帧率、不正确的音效、Setting 仅对本地可见，以及各种严重的 BUG。

6.
以上即为 Test 3 的全部历程。从 2025 年 11 月起，Test 3 由 Test 9 正式取代。

7.
如果您对 Test 3 的更新感兴趣的话，不妨加入 Discord 查看完整的 Test 3 更新日志，我目前仍然保留了 Test 3 的全部更新日志。


关于项目的结语

我并不知道该如何总结这一项目。虽然 Test 3 已停止维护，但 Test 9 已完整覆盖了 Test 3 的所有功能，因此我对其停用并没有特别强烈的情绪。
不过，正是 Test 3 的反复尝试与失败，让我逐步掌握了更复杂的脚本编写方式，也为 Test 9 的开发奠定了重要基础。

Test 9 介绍说明

项目概述

Test 9 是从零重构的 VRChat 节奏类世界，目标是复刻并贴近 Dance Rush 的玩法体验，同时解决 Test 3 中存在的性能、判定与稳定性问题。Test 9 在架构、判定逻辑、谱面解析、音效与 UI 等方面均进行了全面重做，并新增多人（2P）模式、进阶的排行榜、搜索与相机系统等功能。虽然目前仍处于测试阶段，但已实现显著的性能与体验改进。

核心改进（相较于 Test 3）

1. 完全重写框架
   - Test 9 为全新 Unity 项目，不再基于 Test 3 的代码进行修改。
   - 大量移除对 Unity 组件的即时依赖，避免在每帧 Update 中重复计算，从根本上降低运行开销。

2. 性能提升
   - 通过删除占用资源的组件与简化运行时逻辑，Test 9 在相同硬件下帧率显著提升。
   - 开发者端测试：Test 3 大约为 45 FPS；Test 9 在相同条件下可达 140+ FPS；在 VR 模式下约为 60–70 FPS（视客户端设备配置而定）。

3. 更精确的判定系统
   - 放弃基于分段检测的旧方法，采用“整体检测区域 + 时间差计算”的判定策略：触发时根据当前时间与 Note 标记时间的差值直接计算分数，降低检测组件数量并提高判定精度。
   - 针对长条（slider）类音符的处理已改进：在谱面转换阶段计算并写入细化检测点，只有真正结束位置会触发结束音效（SE），避免重复或错误触发。

4. 输入与检测改进
   - 玩家控制器重做：追踪点放置于脚掌前部以获得更稳定的踩踏判定。
   - 新增深度检测机制：根据踩踏深度动态放大判定范围，使玩家能感知踩踏深浅并获得更连贯的反馈。

主要功能一览

1. 谱面与解析
   - 支持基于最新版谱面格式的完整谱面解释器（已兼容官方源文件转换）。
   - 自定义谱面支持计划中；自定义谱面经转换后将获得与官方谱面一致的运行效果。
   - 对 slider 与长条的解析更为精确，检测点间隔在转换时直接生成。

2. 判定与校准
   - 更精细的判定等级与时机校准支持（Offset、Note Speed 等）。
   - 判定依赖时间差计算，提升一致性与可预测性。

3. 多人玩法
   - 新增 2P 模式（目前开放两个并行游玩位置；理论上支持更多但受性能限制，现以 2P 满足多数玩家共同游玩需求）。
   - 2P 为并行独立游玩位置，支持同步开始同一首歌（类似 osu! 的多人房、Beat Saber 的多人玩法）。

4. 排行榜与数据
   - 全新世界排行榜设计，存储玩家 ID 时具备更高容错性（避免特殊字符导致报错）。
   - 支持记录并显示玩家国家/地区信息（排行榜显示国家/地区国旗）。
   - 排行榜数据处理更安全、更稳定。

5. 搜索与歌曲管理
   - 随机歌曲功能。
   - 精细化搜索：可依据歌曲 ID、歌曲名、艺术家、歌曲等级等字段查询。

6. 视觉与音效
   - 延续 Test 3 的舞台风格：黑色地面与墙体、两侧随音乐节奏移动的蓝色光效。
   - 对素材与呈现方式进行优化，踩中 Note 会有对应的分数提示特效。
   - 音效系统重写：踩踏时会产生对应音效，slider 的结束音效仅在真正结束处播放。

7. MV 与视频播放
   - MV 播放逻辑优化：能够在多数情况下正确同步视频进度（仍受玩家加载速度或网络延迟影响）。

8. 相机系统
   - 引入新的相机系统：可对玩家进行拍摄并添加 Dance Rush 风格特效，支持谱面录制与观赏展示。

9. 本地化与 UI
   - 本地化支持增强：不仅能更换文本，还能修改文本大小、颜色等（支持 TMP 的文本标记）。
   - Setting 菜单效果可同步给其他玩家（Setting 的视觉/判定相关变更可被他人看到）。

技术与架构要点

1. 零依赖的运行时结构
   - 移除频繁在 Update 中运算的 Unity 组件，改为事件驱动或精选调度更新，以减少主线程负担。

2. 判定计算模型
   - 所有判定以时间轴为中心：当检测区域被触发时，系统依据触发时间与目标 Note 时间差计算判定等级，减少重复检测与噪声。

3. 深度检测
   - 通过读取追踪器位置与预设触发区域的相对位移，推算玩家踩踏深度并据此调整判定半径与反馈强度。

4. 谱面转换流程
   - 在谱面导入/转换阶段预计算检测点列表（包括 slider 的中间检测点），减少运行时计算压力，并确保音效与判定一致性。

兼容性与依赖

1. 硬件
   - 依赖 VRChat 的脚部追踪器（至少双脚 Tracker）以获得最佳体验。
   - 性能表现将随玩家设备差异显著波动；高配设备能够在 VR 下达到更高帧数。

2. 版权说明
   - 当前 Test 9 支持通过转换得到的 Dance Rush 官方谱面，并规划支持玩家自制谱面。
   - 若使用官方或第三方受版权保护的音乐/谱面，请注意版权合规问题。项目本身未声明或获得第三方官方授权，发布或商业使用时请遵守相关版权法规与平台规则。

已解决的 Test 3 遗留问题（示例）

1. 固定 Note 尺寸假设已移除，支持变长与多样化的 Note 表现。
2. slider 结束音效错误触发问题已修正，仅在真正结束位置播放结束 SE。
3. Setting 菜单仅本地可见的问题已修复（支持同步）。
4. 大量 Update 组件导致的低 FPS 问题已被结构性优化解决。
5. 多项严重 BUG 与同步问题已大幅减少或消除。

当前状态与后续计划

1. 当前版本：仍处于测试版（但已具备良好可玩性）。
2. 后续计划（短期）
   - 完善本地化（更多语言包与 TMP 格式支持）。
   - 完善自定义谱面导入流程并扩大兼容性。
   - 继续修复少数平台/配置下的兼容性问题。
3. 后续计划（中期）
   - 增强多人体验（在保证稳定与性能前提下探索更多并发游玩方式）。
   - 丰富相机/录制功能与社区展示工具。
4. 上线目标
   - 在完成优化与本地化后，发布正式版本并建立稳定的社区反馈与维护机制。

开发理念与最终目标

Test 9 的开发理念是“在最佳性能下实现贴近街机原作的脚部节奏体验，并构建一个稳定友好的社区平台”。最终目标包括：

- 提供稳定、准确、且低延迟的节奏判定体验；
- 在多数硬件下保持流畅运行；
- 支持便捷的谱面管理与社区分享；
